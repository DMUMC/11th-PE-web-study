## 1. 인증과 인가

서비스를 이용하다 보면 로그인이 필요한 기능이 있어요. 로그인한 뒤에도 이용 중인 플랜이나 부여받은 권한에 따라 볼 수 있는 정보가 달라지기도 해요. 

이때 사용자가 누구인지 확인하는 과정은 **인증**, 그 사용자가 어떤 기능이나 데이터에 접근할 수 있는지 판단하는 과정은 **인가**라고 해요.

## 2. JWT를 이용한 인증 및 인가

로그인에 성공하면 서버가 JWT를 발급하고, 클라이언트는 이후 요청에 함께 보내요. 서버는 토큰의 서명과 만료 시간을 검증해 사용자를 확인하고 접근 권한을 판단해요.

- 2.1 JWT란?
    
    **JWT(JSON Web Token)**는 사용자 정보 등을 담아 전달하는 토큰이에요. 서명된 JWT는 점(`.`)으로 구분된 세 부분으로 구성돼요.
    
    - **header**: 토큰 유형과 서명 알고리즘
    - **payload**: 사용자 정보와 만료 시간 등을 담는 부분. 각 정보 항목을 **클레임(claim)**이라고 해요.
    - **signature**: 변조 여부를 검증하는 서명
    
    ![image.png](image%202.png)
    
    인코딩된 토큰의 내용을 읽을 수 있는 형태로 바꾸는 것을 **디코딩**이라고 해요. [JWT Debugger](https://www.jwt.io/)에서 예제 JWT의 내용을 확인해 보세요.
    
    payload는 암호화되지 않으므로 비밀번호 같은 민감한 정보를 담으면 안 돼요.
    
    ![image.png](image%203.png)

- 3.2 회원가입 폼 구현
    
    `signup-page.tsx`의 기존 코드를 아래 코드로 교체해요. 입력값은 `useState`로 관리하고 각 필드의 유효성을 검사해요.
    
    ```tsx
    import { useState } from "react";
    
    // 이메일 형식 검사
    const EMAIL_REGEX = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
    // 영문 대소문자, 숫자, 특수문자(!@#$%^&*)를 모두 포함해 8자 이상
    const PASSWORD_REGEX =
      /^(?=.*[a-z])(?=.*[A-Z])(?=.*[0-9])(?=.*[!@#$%^&*])[A-Za-z0-9!@#$%^&*]{8,}$/;
    
    const DEFAULT_FORM = {
      email: "",
      nickname: "",
      password: "",
      passwordConfirm: "",
    };
    
    type DefaultFormKey = keyof typeof DEFAULT_FORM;
    type DefaultFormValue = (typeof DEFAULT_FORM)[DefaultFormKey];
    
    export function SignupPage() {
      const [form, setForm] = useState(DEFAULT_FORM);
    
      // 입력값의 유효성 검사
      const isEmailValid = EMAIL_REGEX.test(form.email.trim());
      const isNicknameValid =
        form.nickname.trim().length >= 2 && form.nickname.trim().length <= 12;
      const isPasswordValid = PASSWORD_REGEX.test(form.password);
      const isPasswordConfirmValid =
        form.passwordConfirm.length > 0 && form.password === form.passwordConfirm;
    
      // 입력을 시작한 필드에만 오류 표시
      const showEmailError = form.email.length > 0 && !isEmailValid;
      const showNicknameError = form.nickname.length > 0 && !isNicknameValid;
      const showPasswordError = form.password.length > 0 && !isPasswordValid;
      const showPasswordConfirmError =
        form.passwordConfirm.length > 0 && !isPasswordConfirmValid;
    
      // 모든 입력값이 유효하면 제출 버튼 활성화
      const isFormValid =
        isEmailValid &&
        isNicknameValid &&
        isPasswordValid &&
        isPasswordConfirmValid;
    
      const handleChangeField = (key: DefaultFormKey, value: DefaultFormValue) => {
        setForm((prev) => ({ ...prev, [key]: value }));
      };
      
      const handleSubmit = (e:React.SubmitEvent<HTMLFormElement>) => {
    	  // 폼 제출 시 페이지 새로고침 방지
        e.preventDefault()
        
        // 3.4에서 회원가입 API 요청 추가
      };
      
      // noValidate는 폼 제출 시 브라우저의 기본 유효성 검사를 끔
      return (
    	  <form onSubmit={handleSubmit} noValidate>
          {/* UI 구현 */}
          <button type="submit" disabled={!isFormValid}>
            가입하기
          </button>
    	  </form>
      )
    }
    ```

- 3.3 이메일, 닉네임 중복 확인
    
    입력 형식이 올바르더라도 이미 사용 중인 이메일이나 닉네임으로는 가입할 수 없어요. 서버에 중복 여부를 확인하는 기능을 추가해요.
    
    5주차 서버 워크북에서 만든 중복 확인 API를 사용해요.
    
    - 이메일 중복 확인: `GET /members/email/{email}`
    - 닉네임 중복 확인: `GET /members/nickname/{nickname}`
    
    응답의 `available`이 `true`면 사용 가능하고, `false`면 이미 사용 중이에요.
    
    **1. 중복 확인 요청 함수 작성하기**
    
    5주차처럼 클라이언트와 endpoint별 요청 함수를 분리해요.
    
    `src/config/env.ts`의 기존 `env` 객체에 회원 서버 주소를 추가해요. `.env.local`의 `VITE_API_BASE_URL`은 `http://localhost:8080`으로 설정해요.
    
    ```tsx
    apiBaseUrl: import.meta.env.VITE_API_BASE_URL || '',
    ```
    
    `src/api/api-client.ts`를 만들어요.
    
    ```tsx
    import ky from "ky";
    import { env } from "../config/env";
    
    export const apiClient = ky.create({ baseUrl: env.apiBaseUrl });
    ```
    
    `src/api/members/check-email-duplicate.ts`를 만들어요.
    
    ```tsx
    import { apiClient } from "../api-client";
    
    export interface CheckEmailDuplicateResponse {
      available: boolean;
    }
    
    export function checkEmailDuplicate(email: string) {
      return apiClient
        .get(`members/email/${encodeURIComponent(email)}`)
        .json<CheckEmailDuplicateResponse>();
    }
    ```
    
    `src/api/members/check-nickname-duplicate.ts`를 만들어요.
    
    ```tsx
    import { apiClient } from "../api-client";
    
    export interface CheckNicknameDuplicateResponse {
      available: boolean;
    }
    
    export function checkNicknameDuplicate(nickname: string) {
      return apiClient
        .get(`members/nickname/${encodeURIComponent(nickname)}`)
        .json<CheckNicknameDuplicateResponse>();
    }
    ```
    
    **2. 확인 결과를 폼에 연결하기**
    
    `signup-page.tsx` 상단에 import와 아래 상수, 타입을 추가해요.
    
    ```tsx
    import { checkEmailDuplicate } from "@/api/members/check-email-duplicate";
    import { checkNicknameDuplicate } from "@/api/members/check-nickname-duplicate";
    
    const DEFAULT_DUPLICATE_CHECK = {
      isChecking: false,
      isAvailable: false,
    };
    
    type DuplicateCheckKey = "email" | "nickname";
    ```
    
    `SignupPage` 안에 아래 상태를 추가해요. `canSubmit`은 기존 `isFormValid` 아래에 작성하고, `handleChangeField`는 교체해요. `handleCheckDuplicate`는 새로 추가해요.
    
    ```tsx
    const [duplicateCheck, setDuplicateCheck] = useState({
      email: DEFAULT_DUPLICATE_CHECK,
      nickname: DEFAULT_DUPLICATE_CHECK,
    });
    
    // 입력 조건과 두 중복 확인을 모두 통과해야 제출 가능
    const canSubmit =
      isFormValid &&
      duplicateCheck.email.isAvailable &&
      duplicateCheck.nickname.isAvailable;
    
    const handleChangeField = (key: DefaultFormKey, value: DefaultFormValue) => {
      if (key === "email" || key === "nickname") {
        if (duplicateCheck[key].isChecking) return;
        // 확인한 값을 바꾸면 다시 중복 확인해야 함
        setDuplicateCheck((prev) => ({ ...prev, [key]: DEFAULT_DUPLICATE_CHECK }));
      }
      setForm((prev) => ({ ...prev, [key]: value }));
    };
    
    const handleCheckDuplicate = async (key: DuplicateCheckKey) => {
      const isValid = key === "email" ? isEmailValid : isNicknameValid;
      if (!isValid || duplicateCheck[key].isChecking) return;
    
      const label = key === "email" ? "이메일" : "닉네임";
      setDuplicateCheck((prev) => ({
        ...prev,
        [key]: { isChecking: true, isAvailable: false },
      }));
    
      try {
        const response =
          key === "email"
            ? await checkEmailDuplicate(form.email.trim())
            : await checkNicknameDuplicate(form.nickname.trim());
        const isAvailable = response.available;
        setDuplicateCheck((prev) => ({
          ...prev,
          [key]: { ...prev[key], isAvailable },
        }));
        alert(
          isAvailable
            ? `사용할 수 있는 ${label}이에요.`
            : `이미 사용 중인 ${label}이에요.`,
        );
      } catch {
        setDuplicateCheck((prev) => ({
          ...prev,
          [key]: { ...prev[key], isAvailable: false },
        }));
        alert("중복 확인에 실패했어요. 다시 시도해 주세요.");
      } finally {
        setDuplicateCheck((prev) => ({
          ...prev,
          [key]: { ...prev[key], isChecking: false },
        }));
      }
    };
    ```
    
    값을 수정하면 해당 필드의 확인 결과를 초기화해요. 요청 중에는 해당 입력과 중복 확인 버튼을 비활성화해요.
    
    **3. 중복 확인 버튼 연결하기**
    
    기존 이메일 중복 확인 버튼을 수정해요. 확인 결과와 요청 실패는 `alert`로 안내해요.
    
    ```tsx
    <button
      type="button"
      disabled={!isEmailValid || duplicateCheck.email.isChecking}
      onClick={() => handleCheckDuplicate("email")}
    >
      {duplicateCheck.email.isChecking ? "확인 중" : "중복 확인"}
    </button>
    ```
    
    - 이메일 input에 `disabled={duplicateCheck.email.isChecking}`을 추가해요. 기존 `value`와 `onChange` 연결은 유지해요.
    - 닉네임도 같은 방식으로 연결해요. `email`을 `nickname`으로, `isEmailValid`를 `isNicknameValid`로 바꿔요.
    - 가입하기 버튼의 조건을 `disabled={!canSubmit}`으로 바꿔요. 기존 입력 조건과 두 중복 확인을 모두 통과해야 활성화돼요.

- 3.4 회원가입 API 연결
    
    6주차 서버 워크북의 `POST /members`에 회원가입을 요청해요.
    
    **1. 회원가입 요청 함수 작성하기**
    
    `src/api/members/signup.ts`를 만들어요.
    
    ```tsx
    import { apiClient } from "../api-client";
    
    export interface SignupRequest {
      email: string;
      nickname: string;
      password: string;
    }
    
    export interface SignupResponse {
      isSuccess: boolean;
      code: string;
      message: string;
      result: {
        memberId: number;
        email: string;
        nickname: string;
      };
    }
    
    export function signup(body: SignupRequest) {
      return apiClient.post("members", { json: body }).json<SignupResponse>();
    }
    ```
    
    `passwordConfirm`은 화면에서만 검사하므로 요청에 포함하지 않아요.
    
    **2. 폼 제출 처리하기**
    
    `signup-page.tsx` 상단에 요청 함수를 import해요. 로그인 이동 코드는 페이지를 연결한 뒤 사용할 수 있도록 주석으로 남겨요.
    
    ```tsx
    import { signup } from "@/api/members/signup";
    // import { useNavigate } from "@tanstack/react-router";
    ```
    
    `SignupPage` 안에 제출 상태를 추가하고, 기존 `handleSubmit`을 교체해요.
    
    ```tsx
    const [isSubmitting, setIsSubmitting] = useState(false);
    // const navigate = useNavigate();
    
    const handleSubmit = async (e: React.SubmitEvent<HTMLFormElement>) => {
      e.preventDefault();
      if (!canSubmit || isSubmitting) return;
    
      setIsSubmitting(true);
      try {
        const response = await signup({
          email: form.email.trim(),
          nickname: form.nickname.trim(),
          password: form.password,
        });
        alert(response.message);
        // 로그인 페이지 연결 후 주석 해제
        // navigate({ to: "/login" });
      } catch {
        alert("회원가입에 실패했어요. 다시 시도해 주세요.");
      } finally {
        setIsSubmitting(false);
      }
    };
    ```
    
    성공하면 서버의 메시지를 alert로 보여줘요. 실패하면 입력값을 유지한 채 다시 요청할 수 있어요.
    
    **3. 가입하기 버튼 연결하기**
    
    `form`의 `onSubmit={handleSubmit}`은 유지해요. 가입하기 버튼은 요청 중 비활성화하고 문구를 바꿔요.
    
    ```tsx
    <button type="submit" disabled={!canSubmit || isSubmitting}>
      {isSubmitting ? "가입 중" : "가입하기"}
    </button>
    ```
    
    API가 늘어나면 요청 상태와 성공, 실패 처리도 반복해서 작성해야 해요. 8주차에서는 `useMutation`으로 이 코드를 정리해 볼 거예요.

    **`해결`**
    
    👉 `g`를 제거한 뒤 같은 이메일로 `test()`를 반복 호출해 결과가 일정한지 확인했어요.
    
    **`배운 점`**
    
    👉 입력값 전체가 조건을 만족하는지 검사할 때는 `g` 플래그를 붙이지 않아요.
