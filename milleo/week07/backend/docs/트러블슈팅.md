# 트러블슈팅

## 기존 로그인 방식과 JWT 미션의 불일치
- 문제: 초기 연결본은 세션·CSRF 방식이어서 로그인 응답에 accessToken이 없고, Bearer 요청으로 인증할 수 없었습니다.
- 원인: 프론트 연결을 먼저 구현하면서 백엔드 7주차의 JWT 요구사항을 반영하지 못했습니다.
- 해결: BCrypt 검증 후 JJWT로 HS256 토큰을 발급하고 AuthInterceptor에서 서명·만료를 검증합니다. 프론트도 Authorization 헤더를 사용하도록 함께 수정했습니다.
- 검증: 정상 토큰 200, 토큰 누락 AUTH401_2, 변조 AUTH401_3, 만료 AUTH401_4 통합 테스트 통과.

## 클라이언트 memberId를 신뢰하던 평점 API
- 문제: 6주차 URL의 memberId만으로는 요청자 신원을 확인할 수 없습니다.
- 해결: 쓰기 경로를 /ratings로 변경하고 검증된 JWT에서 memberId를 가져옵니다. 서비스에서 평점 작성자를 비교합니다. 요청 DTO에 없는 memberId 전달도 거부합니다.
- 검증: 본인 등록 201·수정 200·삭제 200, 다른 회원 수정 RATING403_1, 없는 평점 RATING404_1, 위조 body 400 및 예전 쓰기 경로 405 확인.

## 회원 화면·영화 조회 연결
- 기존 로컬 TMDB 설정을 Git에 넣지 않고 재사용하여 실제 영화 20건/200을 확인했습니다.
- 임시 프로필을 제거하고 회원가입·로그인·내 정보 API를 연결했습니다.
